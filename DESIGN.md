# LUMEN — Design system

## 0. Research log
- Reference: BibleCast translations catalogue and application screenshot (https://biblecast.app/). Adapt the operator/preview/output separation and quiet native-tool density; this is inspiration, not a pixel clone or reuse of brand assets.
- Direction: a warm editorial control room, blue actions, cream canvas and an ink-blue projection with a small amber horizon. Scripture has serif typography; control labels remain crisp sans serif.
- Desktop native application; browser builds are a component and responsive harness, never a substitute for native media/display APIs.

## 1. Atmosphere & identity
A calm booth for worship. The signature is the contrast between a warm, readable Bible page and a dark luminous audience screen. LUMEN and its sun-ray mark are original. Tagline: La Palabra que ilumina, la alabanza que inspira.

## 2. Color
Tokens: canvas #f6f5f1; panel #ffffff; inset #f0efeb; line #e5e4de; ink #262c32; muted #697079; faint #687079; accent #315cba; accent-hover #264c9f; accent-soft #edf1fb; gold #c29b55; gold-ink #88652f (small text on light surfaces); gold-soft #f7f0e2; green #247556; green-soft #e9f4ef; danger #b64141; projection #111d32; projection-light #263e5c; projection-glow #736344; white #ffffff; black #000000.

## 3. Typography
Operator appearance: Ajustes > Apariencia de la aplicación offers Claro (default), Oscuro and Usar el tema de Windows. Changes apply immediately and persist in the operator WebView's local storage. System mode follows live OS changes. This preference never changes the audience output, media, saved projection backgrounds or QR colors. Dark tokens: canvas #131820; panel #1b222c; inset #252e3a; line #384454; ink #edf1f7; muted #b3becc; faint #a4b1c2; accent #8eb1ff; accent-hover #acc5ff; accent-soft #273753; on-accent #101826; gold-ink #dec28c; gold-soft #3a3225; green #83d4b0; green-soft #203b32; danger #ffaaaa; shadow #00000040. Light on-accent remains white. Native inputs and scrollbars follow color-scheme. Theme changes have no full-page animation; keyboard focus and reading position are preserved.

UI: Segoe UI, system-ui, sans-serif (offline). Scripture: Georgia, Times New Roman, serif. Scale: caption 11/12px; small 13/14px; body 16px; lead 18px; title 24/28px; display 32px. Scripture 24px with 1.8 line height; output uses container-relative fitting from the 24–76 operator setting and shrinks further as needed to fit the selected passage. Labels use 500/600 weight; reading text 400. Maximum two families.

## 4. Spacing & layout
Programa and Ajustes use one column across the entire workspace at every breakpoint. Bible and hymnal library columns must never be inherited by these full-width views.
4px base: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64px. Header 76px; navigation 208px; library 300px; output inspector 340px; reading column fills available width. Main height fills viewport; each long list owns its scroll. At 1180px hide nav labels and narrow the rail; at 960px stack output below the Bible; at 640px use a single-column document and horizontally arranged navigation. Minimum desktop window 960×680; responsive web harness supports 375px. Radii 6/10/16px, pill 999px.

## 5. Components
- Sidebar utility navigation follows the supplied Cantoral reference: Biblia/Himnario/Programa stay at the top, with ¿Cómo funciona? immediately above Ajustes anchored at the bottom. Utility actions retain visible text and keyboard focus; on narrow phone layouts they form a second compact navigation row. The help action opens a labelled native modal with a plain-language four-step guide, a remote-control tip, explicit close and Entendido actions, and Escape dismissal. It never changes live output. While help is open, global projection shortcuts are suspended. The guide scrolls internally up to 90vh, uses shared surface/text/border/radius tokens and restores focus to its sidebar trigger when closed.
- Configuration reference: supplied Cantoral screenshot and local read-only ConfigView.tsx. Preserve its flat horizontal tabs (44px targets, 2px active underline), restrained 10px cards with 16/20px padding, three theme preview choices, three interface-size choices and two developer rows with circular initials. LUMEN adapts tabs to General, Biblioteca, Proyección, Control remoto, Acerca de; no unrelated singer controls or nonfunctional backup/startup controls. The workspace spans the full area beside navigation, with no projection inspector in Configuración. Normal/Grande/Muy grande scale only the operator interface (1/1.1/1.2), persist locally, and use Ctrl +/- and Ctrl 0 (Normal). Theme mini-preview tokens from the reference: light #f7f8fa, sidebar #eef0f4, accent #3a4d8f, line #cbd1da; dark #14171c, sidebar #0f1216, accent #8ba1e6, line #3e4552. The three native buttons expose pressed state and keyboard focus; system preference follows live OS changes. Tabs support Left/Right/Home/End and preserve the selected section during backend snapshots. Credits retain Eliezer Lorenzo (Desarrollo y Diseño) and Ezequiel Sierra (Desarrollo); do not invent social profiles.
- Daily workspace: remove decorative breadcrumb, testament overline, tagline and navigation quote from the initial visual hierarchy. Keep library, quick chapter/verse selection, prepared preview and explicit show/play action. Actual live screen artwork is under Ver pantalla de la iglesia, while live identity, pause, stop and blackout remain visible. This reduces duplicate previews without removing controls. No audience output or media playback changes.
- About and updates: Ajustes links to a real Acerca de LUMEN section with the running version, quiet GitHub release checking, explicit Download and Install actions, a startup-check preference and native progress. Never download/install automatically or restart during projection; installation requires a ready download and closed output. Credits show Eliezer Lorenzo — Desarrollo y Diseño and Ezequiel Sierra — Desarrollo in two responsive rows with EL/ES initials and existing canvas/panel/accent tokens. Initial, checking, current, available, downloading, downloaded, error and development/portable states remain explicit. Release notes are escaped plain text. Local Bible folder import reuses native folder selection and existing translation validation, skips installed IDs, reports errors per file, and never includes local translations in the public repository.
- Remote control: Ajustes owns explicit Enable/Disable, a LAN address, six-digit pairing PIN, linked-phone count and code rotation. Disabled on each app start. Phone browser uses the same offline LUMEN tokens and native controls, 44px minimum touch targets, three labelled tabs (Bible, Hymnal, Program), a text-only live monitor and explicit projection actions. Preparation never changes output. Connection loss disables commands and reports retry; no audio/video plays on the phone. Local selection survives live updates and tab switches. Pairing, loading, error, empty, preparing, paused, blacked-out and disconnected states use words as well as color. Long lists own a bounded scroll and empty search results remain explicit. Phone page fits 375/768/1280px, centered at 780px maximum width. Private LAN access uses an ephemeral PIN and revocable browser sessions; remote routes expose only projection controls and sanitized catalogue data, never local paths, files or import/delete/settings actions.
- Button: icon + text; primary, secondary, ghost, danger; default, hover, active, focus, disabled, pending. Buttons remain native keyboard elements, 36–40px height. Visible 2px focus ring, never color-only meaning.
- Navigation: SVG icon + label + optional count. Active soft-blue fill, left indicator; keyboard reachable. No emoji icons.
- Library row: number + title + metadata; selectable; selected soft blue and border accent. Full-width native button. Long titles wrap.
- Verse row: number + serif text + add-to-program action. Selected verse uses left blue rule. Click selects; double click projects. Enter in quick reference searches; dedicated Project action prevents accidental live changes unless automatic mode is enabled.
- Screen preview: 16:9 container, same renderer/style as output; PREVIA / EN VIVO label, distinct state indicator. Preview video is muted; projection owns audio.
- Audience window: native fullscreen on the designated display, frameless and without a menu, covering the whole display bounds rather than the desktop work area. The operator retains its normal window. Reopening or changing displays reuses the output window; Escape in output closes only that window.
- Base screen image: Ajustes provides an image selector/import, fit mode, local preview, explicit Apply/Discard and Restore LUMEN actions. The image replaces the welcome artwork only, including idle output after stopping a hymn. Bible appearance and hymn media stay independent. Imported images are managed offline assets; a failed image reveals the original welcome screen.
- Inspector section: overline heading, body, compact inputs. Native labelled selects, range inputs, checkboxes; empty/error/loading messages remain visible.
- Operator selects use the application surface, ink, line and accent tokens for both the trigger and the open menu in light/dark mode. Single-selects opt into CSS `base-select` when supported: 36px minimum targets, 8/12px option padding, 4px menu inset, 10px menu radius, 6px option radius, and the existing subtle floating shadow. Selected rows use accent-soft/accent with a checkmark; hover uses inset; keyboard focus has an inset accent outline. Menus render in the browser top layer, wrap long option labels, scroll within 320px or half the viewport, and stay within the viewport width. Native labels, values, forms, change events, keyboard navigation, Escape and focus handling remain intact; no JavaScript replacement. Unsupported runtimes retain functional native pickers. Remote phone controls keep their native mobile picker and 44px targets; audience output is unaffected.
- Projection context: identify the active preparation section and selected passage or hymn above its preview. The live monitor names its actual content independently. Bible mode owns typography, backgrounds and automatic verse projection; hymn mode owns audio mode, volume and transport. Pending, playing, paused, hidden and idle are explicit text states. Stop clears a hymn; pause retains its position. Transport for an actual live hymn remains reachable when the operator navigates to another section. Program and settings views show monitoring without reusing a stale Bible selection.
- Toast: persistent live region for actionable failures, dismiss button; normal progress status is separate and not color-only.
- Program item: title, category, remove button; click selects; up/down controls reorder. Empty state explains next action. JSON persistence belongs to main process.
- Translation comparison: labelled second-edition selector, two text columns with their actual references, explicit missing-reference state, and a dedicated projection action. Stacks on narrow screens. Selecting a comparison never silently replaces live output.
- Quick navigator: book list/grid switch plus native chapter and verse selectors. Library grid owns its vertical scroll; long names retain accessible full labels.
- Translation catalogue: local-edition cards with provenance/offline permission, explicit network catalogue refresh, and download actions with progress. Startup never requests Internet access; installing a translation commits only after every book succeeds.
- Hymn filters: edition (also assigned when importing), search field scope, and favourite toggle. Metadata form adds optional lyrics, topic, authors, references and explicit sung/instrumental audio mappings. Draft values survive snapshots. No lyrics or authors are fabricated from MKV names.
- Hymnal editions: Antiguo1962 and Nuevo2009 are visible native choices with available counts and pressed states; Todos and Sin identificar remain reachable. Edition changes select the numbering used for search, sorting and display. The detail shows both references, missing equivalences and source collisions explicitly. One stable media identity serves both views; labels explain that the available video is preserved. Number edits are explicit metadata changes, never inferred from a number alone.
- Complete old catalogue: all527canonical titles remain searchable without local media. Catalogue metadata is separate from files; absent media shows Canción no disponible and disables projection/programme actions. Canonical numbers are unique; conflicting media references stay visible for review, and an exact title match can identify the available file without changing saved mappings. Browsing an unavailable title never replaces live content.
- Projection history: collapsed native details/list, most recent first; each row has reference/title and translation with an explicit replay button. No media URLs persisted.

## 6. Motion & interaction
Developer credits include compact external-link buttons @elorenzog and @xlCyanz (the latter explicitly confirmed by the user for Ezequiel Sierra). Each has an accessible person-specific label and opens the system browser through a fixed native allowlist. Unknown profiles and requests from audience/remote windows are rejected. On phones the link may wrap below the name rather than compress the developer's name.
Beginner flow: four explicit steps (1 choose book, 2 chapter, 3 verse, 4 review/show). Navigation retains text labels at desktop/tablet widths. The primary Bible action says Mostrar en pantalla; its preview says Así se verá and the actual output says Pantalla de la iglesia. Range selection, comparison, appearance/automatic projection and keyboard shortcuts remain reachable in labelled collapsed details. Their open state survives rerenders. Advanced controls never disappear as features; normal reading has fewer visible choices. The hymn empty state explains choose edition/search, choose audio and play; pause/stop remain explicit.
Phone access is available in Ajustes > Control remoto with three pairing steps (same Wi-Fi, scan QR, enter PIN). The offline QR encodes only the chosen local URL, never the PIN, with black modules on white and a four-module quiet zone. Multiple network addresses use one labelled selector that updates the QR. The URL remains selectable and troubleshooting lives in collapsed details. Scripture preparation explains manual versus automatic projection; Bible book names remain complete rather than cut-off abbreviations.
Selecting a verse reveals its scripture row inside the bounded verse reader, including quick selection, typed ranges and keyboard navigation. Only this viewport scrolls; unrelated renders and live snapshots preserve manual reading position. A newly selected row uses the nearest visible edge, or its beginning if taller than the viewport, without shifting chapter controls or other panels.
Quick passage selection adds a default book grid, chapter/verse number buttons (36px targets, 8px gap, selected blue fill and aria-pressed), a six-verse range field and Ctrl+L reference focus. Chapter buttons live in a bounded scroll region; scripture keeps its own scroll. Book/chapter navigation prepares context; only verse selection sends live output when automatic mode is enabled.

Appearance editor: a labelled native modal dialog, two columns on desktop and one on mobile, maximum 1100px width and 90vh height. Left: live draft preview and saved themes; right: grouped background/text/layout controls. Import copies image/video into managed offline assets. Apply commits, Cancel preserves the current live theme. Use existing surface, line, accent, spacing and type tokens; draft settings never change live output. Backgrounds: built-in, solid, gradient, image and silent loop video. Scripture controls: safe margins, vertical/horizontal alignment, typeface, weight, colors, shadow, outline and line height. Custom theme choices are projector content, independent of operator UI colors. This implements BibleShow's background/text workflow in LUMEN, not a pixel clone, transparent desktop or NDI support.

120ms ease-out opacity/transform only. Button active shifts 1px. No decorative continuous animation. Reduced-motion removes transitions. Manual project by default; an explicit automatic projection toggle sends selection immediately. Arrows navigate verses outside editable controls, B toggles blackout, Escape closes projection. Blackout pauses hymn audio; restoring resumes only if previously playing.

## 7. Depth & surface
Mixed: hairline borders define utility regions; subtle 0 2px 8px #00000008 elevation for floating notices. Reading canvas stays flat. Audience background has layered radial light: projection-light at top-left and projection-glow bottom-right on projection base. Projected text uses ample safe margins and an amber fine rule.

## 8. Accessibility constraints & accepted debt
WCAG 2.2 AA intention: text contrast, visible focus, labelled native controls, live error messages, reduced motion, no keyboard trap, color plus words for live state. Large type on audience output must shrink to fit long passages. Operator personas: volunteer under time pressure; keyboard operator; user with reduced vision. No accepted accessibility debt. Physical projector placement, macOS/Linux packages and actual church MKV codecs require target-hardware validation; report these as untested, not passed.



Remote hymn position is read-only by default. Cambiar posición opens a draft; moving its slider changes only the draft, and Ir a esta posición is the sole seek command. Cancel discards the draft. A changed hymn, track or output revision invalidates confirmation. Vertical page scrolling never commits a seek.
